**cPanelSniper** is a focused exploitation framework for **CVE-2026-41940**, a critical authentication bypass vulnerability in cPanel & WHM. The vulnerability lets unauthenticated remote attackers gain root-level WHM access by injecting CRLF sequences into the on-disk session file via the `Authorization: Basic` HTTP header — no valid credentials required. cPanelSniper automates the complete 4-stage exploit chain and includes an interactive post-exploitation shell, bulk scanning, and pipeline support, all using pure Python 3.8+ stdlib with no external packages.

## What is CVE-2026-41940?

CVE-2026-41940 is a pre-authentication remote code execution vulnerability rooted in `Session.pm`, the session management module in cPanel & WHM. The `saveSession()` function writes session data to disk **before** calling `filter_sessiondata()` for sanitization. This ordering flaw means that CRLF characters embedded in the `Authorization: Basic` header value are written verbatim into the session file on disk, injecting attacker-controlled fields that cPanel then reads back as legitimate session data — granting a fully authenticated root session.

- **CVSS score:** 10.0 (Critical)
- **In-the-wild exploitation:** Confirmed (April 2026)
- **Affected installs:** Approximately 70 million domains running cPanel & WHM
- **Root cause:** `saveSession()` writes the session file before `filter_sessiondata()` sanitizes it

## The CRLF payload

The `Authorization: Basic` value (base64-decoded) injects the following fields directly into the cPanel session file:

```
root:x
successful_internal_auth_with_timestamp=9999999999
user=root
tfa_verified=1
hasroot=1
```

When cPanel reads the session file back, it treats these as legitimate fields and grants full root WHM access without any password check.
